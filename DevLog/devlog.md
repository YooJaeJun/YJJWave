# YJJWave 개발 일지

## 2026-11-22 — 시작: 물량 맞다이의 바탕

- 기획: `Docs/Design.md` (참고작 Here Comes the Horde의 물량 쾌감, 그림·UI는 YJJ식 냥코·졸라맨풍)
- 언리얼 C++ 프로젝트 생성 (UE 5.8.1 소스 엔진). 맵 에셋 없이 HUD 캔버스로 전부 그린다
- 대용량 시뮬 `FYJJHorde`: 유닛 = 배열의 한 칸(SoA), 편별 균일 격자를 매 틱 계수 정렬로 다시 만들고, 대상 찾기·이동·밀어내기는 ParallelFor
- 그리기: 유닛 전부를 아틀라스 한 장 + 캔버스 배치 하나로 (드로우 콜 1번), Y 버킷 정렬. 죽은 몸은 잠깐 날아간 뒤 바닥 렌더 타깃에 피와 함께 구워져 쌓인다 (몇만 구가 쌓여도 비용 0)
- 병영 4종(졸병·궁수·방패·망치 대장), 몬스터 5종(해골·도깨비·뚱보 좀비·해골 궁수·해골 왕 보스), 물결 10레벨 + 무한
- 특성 성좌 65개 별(큰 별 16개), 스펠 2개(유성 낙하·돌격 함성)
- 수치·배치·글자 전부 CSV (Tuning 67, UILayout 136, Localization ko/en)

## 2026-11-22 — 드로우 콜·구간별 측정, 재탐색 버그 수정

- 버그: 시야를 260→700으로 넓힌 뒤 대상이 없는 유닛이 엇갈림 주기를 무시하고 **매 틱** 넓은 시야를 다 뒤졌다 → 2만 vs 2만 21fps. 대상이 방금 죽었을 때만 즉시, 나머지는 주기대로 찾게 고침
- 측정 추가: 시뮬 구간별 시간(격자·생각·전투·정리), 유닛 그리기 CPU 시간 (`[AutoPilot] PHASE` 로그), `RunGame.ps1 -Exec "stat RHI, stat unit"`

| 아군 vs 적 | 시뮬 1틱 | (그중 병렬 생각·이동) | 유닛 그리기 CPU | 프레임 | fps |
|---|---|---|---|---|---|
| 5,000 vs 5,000 | 2.23ms | 1.98ms | 1.84ms | 3.8ms | 261 |
| 10,000 vs 10,000 | 3.88ms | 3.28ms | 4.72ms | 8.0ms | 124 |
| 15,000 vs 15,000 | 5.59ms | 4.77ms | 7.02ms | 11.5ms | 87 |
| 20,000 vs 20,000 | 6.92ms | 5.86ms | 9.18ms | 14.7ms | 68 |

- `stat unit` (4만 마리): Game 14.2ms / Draw(렌더 스레드) 5.0ms / GPU 1.2ms → **게임 스레드가 병목**, GPU는 여유
- `stat RHI` Draws: 1천 마리 112 → 4만 마리 118 (stat 글자 자체 포함). stat RHI 없이 4만 마리 = 58. 유닛이 3만 9천 늘 때 드로우 콜은 6개 증가 (배치가 인덱스 한도로 몇 덩어리로 나뉨)
- 아틀라스를 1024x2048 → 4096x4096(칸 16배)으로 키워도 4만 마리 GPU 1.19ms, 63fps로 차이 없음

## 2026-11-22 — 최적화: GPU 인스턴싱, 비동기 시뮬, 캐시 재배치

- **GPU 인스턴싱** (`Render/YJJSpriteRenderItem`, 셰이더 `Shaders/YJJSprite.usf`, 모듈 `YJJWaveShaders`): 캔버스 정렬 목록에 직접 렌더 아이템을 끼워 넣어, 유닛당 48바이트(위치·UV·색)만 ParallelFor로 채우고 모서리는 정점 셰이더가 만든다. 바닥 → 유닛 → UI 순서는 그대로
- **비동기 시뮬**: 규칙·생산(PreStep)과 연출·보상(PostStep)은 게임 스레드, 유닛 시뮬(Horde.Step)은 작업 스레드. HUD는 프레임 시작에 복사한 `FYJJHordeView`만 읽어 시뮬과 그리기가 겹친다 (`yjj.AsyncSim 0`으로 끔)
- **캐시 재배치**: 30틱마다 살아 있는 유닛을 격자 칸 순서로 슬롯을 다시 채움 (이웃끼리 메모리도 가깝게). 대상·투사체·보스 슬롯은 새 번호로 바꿈
- **격자 병렬**: 두 편 격자를 동시에. 그림자는 확대 0.55 미만에서 생략

4만 마리 (2만 vs 2만, 밀집 구간 평균):

| | 프레임 | fps | 유닛 그리기 CPU | 시뮬 1틱 (생각·이동) |
|---|---|---|---|---|
| 최적화 전 | 14.7ms | 68 | 9.18ms | 6.92ms (5.86) |
| 인스턴싱 + 비동기 + 재배치 | **3.6ms** | **277** | **0.83ms** | 7.62ms (6.86) |
| 위에서 재배치만 끔 | 5.5ms | 180 | 1.14ms | 10.32ms (9.44) |
| 위에서 비동기만 끔 | 5.0ms | 201 | 0.77ms | 7.60ms (6.84) |

- 1만 vs 1만: 3.2ms, 314fps
- 재배치 한 번 2.4~2.9ms (30틱에 한 번이라 틱당 약 0.09ms)
- 시뮬 1틱이 최적화 전보다 조금 늘어난 것은 그리기와 같은 코어를 나눠 쓰기 때문 (프레임 전체는 4배 빨라짐)
